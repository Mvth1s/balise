# Revue de sécurité : constats et suites données

Revue du moteur (`packages/analyzer`), de l'API (`server/`, `api/`) et de la configuration Vercel, menée par l'agent `security-reviewer`. Le détail des protections est dans [`securite.md`](securite.md).

Statuts : **corrigé** (changement de code ou de configuration, testé) ou **risque accepté** (justification donnée, suivi dans `securite.md`, § 8).

## Élevé

| Réf. | Constat                                                                                                                                                                                                                   | Statut                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| E1   | Sur Vercel, les arguments de `@sparticuz/chromium` désactivent la politique de même origine (`--disable-web-security`), autorisent le contenu mixte et l'isolation des sites ; plusieurs `--disable-features` s'écrasent. | **Corrigé** : `buildLaunchArgs` (fonction pure testée) retire `--disable-web-security`, `--allow-running-insecure-content`, `--disable-site-isolation-trials` et `--enable-features=SharedArrayBuffer`, ajoute `--js-flags=--jitless` et `--disable-quic`, fusionne les listes Playwright, Sparticuz et Balise en un seul `--disable-features`. Mode graphique désactivé. **Risque accepté** : `--no-sandbox`, `--single-process` et la désactivation d'`IsolateOrigins`/`site-per-process` sont imposés par Lambda ; secrets dans la même fonction que Chromium (séparation en deux fonctions : piste documentée). |
| E2   | L'analyse n'était interruptible que pendant le chargement : un script de la page bloqué pendant axe-core retenait la fonction jusqu'à `maxDuration`, et l'analyse restait « en cours » pour toujours.                     | **Corrigé** : le signal ferme le navigateur pendant toute l'analyse ; `runAnalysis` applique le plafond par `Promise.race` puis écrit `unreachable` ; une analyse `pending`/`running` sans mise à jour depuis plus de 300 s est renvoyée et enregistrée en erreur `internal`. Test d'intégration avec une page qui bloque le moteur de rendu dès l'injection d'axe-core.                                                                                                                                                                                                                                            |

## Moyen

| Réf. | Constat                                                                                                                                                          | Statut                                                                                                                                                                                                                                                                                                |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| M1   | Limitation de débit contournable en IPv6 (un abonné dispose d'un /64 entier) ; aucun plafond global.                                                             | **Corrigé** : clé = HMAC du préfixe /64 en IPv6 (IPv4 mappée ramenée à l'IPv4), plafond global de 100 analyses par heure (clé `global`), IP lue par `ipAddress()` de `@vercel/functions`. Tests unitaires.                                                                                            |
| M2   | La page pouvait émettre des `POST`/`PUT` avec corps via Balise ; redirections de sous-ressources suivies vers d'autres origines avec les en-têtes du navigateur. | **Corrigé** : seules les requêtes `GET`/`HEAD` sans corps sont exécutées ; les redirections de sous-ressources vers une autre origine sont bloquées, ce qui garantit que `Cookie`/`Authorization` ne changent jamais d'origine (pas de nettoyage séparé nécessaire). Tests d'intégration.             |
| M3   | `POST /api/analyses` acceptait tout type de contenu : un formulaire d'un site tiers pouvait consommer le quota de ses visiteurs.                                 | **Corrigé** : `Content-Type: application/json` exigé (`415 unsupported_media_type`), `Sec-Fetch-Site: cross-site` refusé (`403 forbidden_origin`). Le front envoie déjà `application/json` (`apps/web/src/lib/api.ts`). `docs/api.md` à jour. Tests.                                                  |
| M4   | `helpUrl` et sélecteurs repris tels quels des résultats axe calculés dans la page.                                                                               | **Corrigé** : lien reconstruit côté Node à partir de l'identifiant de règle connu ; types validés ; sélecteurs tronqués à 1 000 caractères. La possibilité pour une page d'influencer son propre résultat est documentée (`securite.md` § 6, `scoring.md` § 6), sans avertissement ajouté au rapport. |

## Faible

| Réf. | Constat                                                                                                      | Statut                                                                                                                                                                                                                                                                                                                   |
| ---- | ------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| F1   | Plafond d'octets cumulés vérifié avant chaque requête : des requêtes parallèles pouvaient le dépasser.       | **Corrigé** : budget partagé, décompté au fil du flux par `safeFetch`. Test unitaire avec deux requêtes parallèles.                                                                                                                                                                                                      |
| F2   | QUIC non désactivé.                                                                                          | **Corrigé** : `--disable-quic` (voir E1).                                                                                                                                                                                                                                                                                |
| F3   | Corps de `POST` lu entièrement avant le contrôle de taille.                                                  | **Corrigé** : `Content-Length` vérifié avant lecture, puis lecture en flux abandonnée au-delà de 8 Kio.                                                                                                                                                                                                                  |
| F4   | `dns_failure` distinct de `forbidden_target` révèle si un nom se résout.                                     | **Risque accepté** : l'information est publique pour les noms publics, les noms internes sont refusés avant résolution, et le code aide l'utilisateur à repérer une faute de frappe.                                                                                                                                     |
| F5   | Dépendances inutilisées (`zod`, `@vercel/node`) ; pas d'audit planifié.                                      | **Corrigé** : les deux paquets sont retirés (aucun import, `vercel.json` ne les exige pas) ; audit hebdomadaire `.github/workflows/audit.yml`. L'audit a révélé `zod` 4.1.11 vulnérable sous `@vercel/cli-config` : corrigé par `overrides` (4.6.7).                                                                     |
| F6   | CSP `script-src` trop large ; `Permissions-Policy` minimale ; pas de `Cross-Origin-Resource-Policy`.         | **Corrigé** : `script-src 'self' https://www.googletagmanager.com/gtag/` (le chemin `/gtag/` couvre `gtag/js` et les scripts complémentaires que celui-ci peut charger), `payment=(), usb=(), browsing-topics=()` ajoutés (`interest-cohort` omis : avertissement console), `Cross-Origin-Resource-Policy: same-origin`. |
| F7   | `scripts/e2e-server.ts` : un chemin commençant par `//` pouvait produire une redirection vers un autre hôte. | **Corrigé** : barres obliques et contre-obliques de tête ramenées à une seule, avant l'analyse de l'URL et avant les redirections.                                                                                                                                                                                       |
